# 二分查找边界问题详解

二分查找看似简单，但边界条件极易出错。核心原因在于：**这些边界条件是互相关联的**，不能孤立地看某一个。

本质上存在**两套自洽的写法**，选定一套后，其余条件就确定了。

---

## 两套经典写法对比

| 要素       | 写法一：闭区间 `[left, right]`     | 写法二：开区间 `(left, right)`  |
| ---------- | ---------------------------------- | ------------------------------- |
| 初始值     | `left = 0, right = arr.length - 1` | `left = -1, right = arr.length` |
| while 条件 | `left <= right`                    | `left + 1 < right`              |
| 找到目标   | `return mid`                       | `return mid`                    |
| mid 偏小   | `left = mid + 1`                   | `left = mid`                    |
| mid 偏大   | `right = mid - 1`                  | `right = mid`                   |

---

## Q1: `left, right` 到底设定为 `(0, arr.length - 1)` 还是 `(-1, arr.length)`？

取决于你把搜索区间定义为**闭区间**还是**开区间**：

### 闭区间 `[left, right]`

```ts
let left = 0,
  right = arr.length - 1;
```

- 含义：left 和 right **都是有效索引**，搜索范围包含两端。
- `right = arr.length - 1` 因为最后一个有效索引就是 `arr.length - 1`。

### 开区间 `(left, right)`

```ts
let left = -1,
  right = arr.length;
```

- 含义：left 和 right **都不在搜索范围内**，它们是边界哨兵，实际搜索范围是 `(left, right)` 即 `left+1` 到 `right-1`。
- `left = -1` 因为 `arr[-1]` 越界，恰好作为左侧"不包含"的边界。
- `right = arr.length` 因为 `arr[arr.length]` 越界，恰好作为右侧"不包含"的边界。
- 这种写法的好处是 **left 和 right 的更新方式完全对称**（都是 `= mid`），不容易出错。

## Q2: `while (left < right)` 还是 `while (left <= right)`？

### 闭区间 → `left <= right`

```ts
while (left <= right) { ... }
```

- 因为当 `left === right` 时，区间 `[left, right]` 仍然包含一个元素，需要被检查。
- 如果写成 `left < right`，会**漏掉最后一个元素**。

### 开区间 → `left + 1 < right`

```ts
while (left + 1 < right) { ... }
```

- 因为开区间 `(left, right)` 中，left 和 right 本身都不在搜索范围内。
- 当 `left + 1 === right` 时，`(left, right)` 之间没有整数索引了，区间为空。
- 当 `left + 1 < right` 时，区间内至少还有一个元素（索引 `left+1` 到 `right-1`）。
- 如果写成 `left < right`，会在只剩一个元素时提前退出，**漏掉最后一个元素**。

> **记忆口诀**：闭区间用 `<=`，开区间用 `left + 1 < right`。本质是判断「搜索区间为空」的条件。

## Q3: `if (arr[mid] < target)` 后，`left = mid` 还是 `mid + 1`？

这里两种写法**不同**：

### 闭区间 → `left = mid + 1`

```ts
if (arr[mid] < target) {
  left = mid + 1; // mid 已排除，闭区间左端推进到 mid+1
}
```

- 因为闭区间中 left 是有效索引，mid 已被比较排除，所以 left 应该移到 `mid + 1`。
- 如果写 `left = mid`，mid 会在下一轮被重复检查（因为闭区间包含 left），可能导致**死循环**。

### 开区间 → `left = mid`

```ts
if (arr[mid] < target) {
  left = mid; // 开区间中 left 本身不包含，所以 mid 恰好被排除
}
```

- 因为开区间 `(left, right)` 中 left 本身就不在搜索范围内，设 `left = mid` 意味着 mid 被排除，下一轮搜索从 `mid + 1` 开始。
- 如果写 `left = mid + 1`，会多排除一个元素（`mid + 1`），导致**漏检**。

---

## Q4: `else` 中 `right = mid` 还是 `mid - 1`？

这里两种写法**不同**：

### 闭区间 → `right = mid - 1`

```ts
if (arr[mid] > target) {
  right = mid - 1; // mid 已排除，闭区间右端收缩到 mid-1
}
```

- 因为闭区间中 right 是有效索引，mid 已被排除，所以 right 应该移到 `mid - 1`。
- 如果写 `right = mid`，mid 会在下一轮被重复检查（因为闭区间包含 right），可能导致死循环。

### 开区间 → `right = mid`

```ts
if (arr[mid] > target) {
  right = mid; // 开区间中 right 本身不包含，所以 mid 恰好被排除
}
```

- 因为开区间 `(left, right)` 中 right 本身就不在搜索范围内，设 `right = mid` 意味着 mid 被排除。
- 如果写 `right = mid - 1`，会多排除一个元素，导致**漏检**。

> **开区间的对称之美**：注意到开区间写法中，`left = mid` 和 `right = mid` 是完全对称的！不需要记 `+1` 还是 `-1`，这正是开区间写法的最大优势。

## 完整代码示例

### 写法一：闭区间（推荐，最直观）

```ts
const binarySearch = (arr: number[], target: number): number => {
  let left = 0,
    right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (arr[mid] === target) return mid;

    if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1; // not found
};
```

### 写法二：开区间（不容易出错）

```ts
const binarySearch = (arr: number[], target: number): number => {
  let left = -1,
    right = arr.length;

  while (left + 1 < right) {
    const mid = Math.floor((left + right) / 2);

    if (arr[mid] === target) return mid;

    if (arr[mid] < target) {
      left = mid;
    } else {
      right = mid;
    }
  }

  return -1; // not found
};
```

## 总结：一张图记住所有边界

```
闭区间 [left, right]          开区间 (left, right)
─────────────────────         ─────────────────────
left  = 0                     left  = -1
right = arr.length - 1        right = arr.length
while (left <= right)         while (left + 1 < right)
  left  = mid + 1               left  = mid
  right = mid - 1               right = mid
```

**核心思想**：所有边界设定围绕一个原则 —— **每次迭代都要缩小搜索区间，且不遗漏、不重复**。
