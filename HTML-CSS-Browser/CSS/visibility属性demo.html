Case 1：保留布局空间的隐藏

使用 visibility: hidden 隐藏中间的蓝色方块，空间仍保留，布局不跳动。

对比 display: none 隐藏，蓝色方块消失，绿色方块会左移。

交互区
A
B
C

📝 代码

/* visibility: hidden — 空间保留，布局不变 */
.box-b.hidden-visibility {
  visibility: hidden;
}

/* display: none — 空间消失，后续元素左移 */
.box-b.hidden-display {
  display: none;
}
💡 典型场景：Tab 切换、骨架屏占位、表格中临时隐藏某行但保持对齐。

Case 2：配合 opacity + transition 实现淡入淡出

visibility 单独使用没有视觉过渡效果（只有 visible / hidden 两态）。

但配合 opacity 使用时，visibility 控制交互时机，opacity 产生平滑过渡。

交互区

📝 代码

.modal-overlay {
  opacity: 0;
  visibility: hidden;
  transition: opacity 0.3s, visibility 0.3s;
}

.modal-overlay.active {
  opacity: 1;
  visibility: visible;
}

/* 显示时：visibility 立即变为 visible（元素可交互），opacity 渐变产生淡入 */
/* 隐藏时：opacity 渐变到 0，visibility 在过渡结束后才变为 hidden */
💡 为什么不能只用 opacity: 0？ 因为 opacity: 0 的元素仍然可以被点击，会遮挡下方内容。
加上 visibility: hidden 可以在动画结束后阻止用户交互。

Case 3：子元素可以单独恢复可见

visibility: hidden 的独特特性：子元素设置 visibility: visible 可以重新显示。

而 display: none 的子元素无论如何都无法显示。

交互区

下方父容器设置了 visibility: hidden，观察两个子元素的表现：

（父容器文字 — 不可见） ✅ 我设置了 visibility: visible ❌ 我没设置，继承 hidden

📝 代码

.parent {
  visibility: hidden;  /* 父容器隐藏 */
}

.parent .child-visible {
  visibility: visible;  /* ✅ 子元素可以单独恢复显示！ */
}

.parent .child-normal {
  /* 没有设置 visibility，继承父级的 hidden，不可见 */
}
💡 典型场景：隐藏父容器但显示其中特定的子元素，如下拉菜单中的某个选项、工具提示等。

Case 4：预渲染 / 测量元素尺寸

需要获取未显示元素的尺寸时，visibility: hidden 可以正常测量。

而 display: none 的元素返回 offsetWidth = 0, offsetHeight = 0。

交互区
visibility: hidden 的元素
display: none 的元素

📝 代码

// visibility: hidden — 可以正常获取尺寸
const visEl = document.getElementById('measure-vis');
console.log(visEl.offsetWidth);   // 280 (250 + padding)
console.log(visEl.offsetHeight);  // 110 (80 + padding)

// display: none — 尺寸返回 0
const dispEl = document.getElementById('measure-disp');
console.log(dispEl.offsetWidth);  // 0 ❌
console.log(dispEl.offsetHeight); // 0 ❌
✅ 最佳实践：需要预渲染计算尺寸时，使用 visibility: hidden。

/* 三种隐藏方式 */
.box-vis  { visibility: hidden; }  /* 空间保留 ✅ | 事件阻断 ✅ */
.box-disp { display:    none;   }  /* 空间消失 ❌ | 事件阻断 ✅ */
.box-opa  { opacity:    0;      }  /* 空间保留 ✅ | 事件仍响应 ⚠️ */

/* opacity: 0 的元素仍然可以被点击，这在很多场景下是一个坑！*/
⚠️ 重点：opacity: 0 的元素仍然会响应鼠标事件，这是它与 visibility: hidden 的关键区别。 如果需要透明但不可点击，需要额外添加 pointer-events: none。

📈 性能对比说明

属性切换 触发阶段 性能影响 优化建议
display: none ↔ block Layout → Paint → Composite
(重排 + 重绘 + 合成)		 ⚠️ 最重：触发完整渲染流水线 避免频繁切换；可用 class 替代
visibility: hidden ↔ visible Paint → Composite
(重绘 + 合成)		 ✅ 较好：跳过 Layout 阶段 适合保留空间的隐藏切换
opacity: 0 ↔ 1 Composite
(仅合成，如果在合成层)		 🚀 最佳：可完全 GPU 加速 配合 will-change: opacity
浏览器通常自动提升合成层
✅ 最佳实践（如本页弹窗）：使用 opacity + visibility 组合 —— opacity 提供平滑动画 + GPU 加速，visibility 在动画结束后阻止交互。
对于简单场景，不需要手动添加 will-change，浏览器在 transition 期间会自动提升到合成层。
